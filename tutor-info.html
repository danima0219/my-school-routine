Project rationale and evidence-informed design specifications

Functional Specifications

This table compares the evidence-informed functional specifications with the current implementation of My School Routine. It identifies existing features, implementation limitations and recommended improvements.

Specification Supporting Sources Functional Requirement Current Prototype Recommended Improvements
E-01: Linear and Uncluttered Navigation Dzaman et al. (2022); CAST (2024); Victorian Department of Education (n.d.) Provide a linear pathway that minimises unnecessary navigation during the activity. The routine sequence is presented on one screen, but external information and educator settings are also accessible. Provide a learner-focused view that minimises access to external links and configuration options during the activity.
E-02: Explicit Next-Step Assessment Trigger Dzaman et al. (2022); CAST (2024) Present an explicit next-step question and require a response before recording completion. The “What comes next?” question requires a response before it can be recorded. Only one question is currently available. Extend the activity to include additional routine steps and assessment opportunities.
E-03: Dual-Factor Performance Logging CAST (2024); alignment of learning outcomes, instructional sequence and assessment Record accuracy and support level: Independent, Verbal Prompt, Gestural Support or Physical Assistance. The log records accuracy and support level, distinguishing independent correct responses from supported correct responses. Ensure consistent recording and interpretation of performance in relation to the learning outcome.
E-04: Dynamic Visual Representation Engine CAST (2024); Knight et al. (2015); AllPlay Learn (n.d.) Allow educators to select suitable photographs, AAC symbols or other visual representations for each learner. Representation options are present, but the photo option is a placeholder and switching is not fully functional. Implement reliable visual switching and allow educators to select appropriate representations for individual learners.
E-05: Strict Visual Card Consistency CAST (2024); Knight et al. (2015) Maintain consistent card dimensions, spacing, borders and typography. The prototype uses consistent card layouts, 4:3 aspect ratios, padding and borders. Text sizes do not consistently meet the proposed 24 pt minimum. Review typography and card dimensions against the specification and test readability on intended devices.
E-06: Purposeful Multimedia Filtering CAST (2024) Exclude unnecessary music, decorative animations and sound effects. Use audio for an instructional or accessibility purpose. There is no background music or decorative animation. Selecting a response automatically triggers browser speech synthesis. Consider educator control over spoken output and test its suitability for different learners.
E-07: Multi-Modal AAC Response Support CAST (2024); Pope et al. (2025); Therrien et al. (2025) Support appropriate input methods, including touch, pointer, keyboard, switch access and compatible AAC systems. Standard HTML buttons support common pointer and keyboard interactions. Dedicated switch access and direct AAC integration have not been implemented or verified. Test assistive-technology access, investigate switch compatibility and assess possible AAC system integration.
E-08: Technical Accessibility and WCAG 2.2 Alignment W3C (2023); CAST (2024) Provide accessible interaction targets, sufficient contrast, visible focus indicators and appropriate accessible names. Buttons and selects have a 48 px minimum height, visible focus styling and reduced-motion support. Contrast and full WCAG 2.2 compliance have not been verified. Conduct an accessibility audit and test contrast, interactive targets, keyboard access and assistive-technology compatibility.
E-09: Contextual Support Differentiation in Reports CAST (2024); alignment of learning outcomes, instructional sequence and assessment Distinguish independent correct responses from correct responses achieved with support. The on-screen log identifies independent and supported correct responses. CSV fields allow these categories to be interpreted together. Add an explicit performance category to the exported report and document how each category should be interpreted.

Evaluation note

The implementation status reflects inspection of the current prototype code. Accessibility, usability and learning effectiveness require separate testing. The supporting references should be checked against the original publications before academic submission.
